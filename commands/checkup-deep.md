# AI 사용설명서 깊은 검진 (SoDamContext — Phase 3)

일반 검진(`/sodam-context:checkup`)이 규칙·키워드로 못 잡는 항목 5가지(모순·맥락 없는
참조·예시 없는 규칙·부풀림·RE 스코프 누락)를 **당신(AI)이 직접 내용을 읽고 판단**합니다.
일반 검진과 달리 **원본 내용의 일부를 실제로 보게 되므로**, 반드시 아래 동의 절차를
먼저 거칩니다.

## ★ 절대 안전 규칙

1. **먼저 동의를 구하세요.** 아래 문구를 그대로(또는 자연스럽게 풀어) 보여주고 사용자의
   확인을 받기 전에는 이 명령의 도구를 실행하지 마세요:
   > "이 검사는 설명서 내용을 제가 직접 읽고 판단합니다(일반 검진보다 토큰을 더 씁니다).
   > 비밀키로 보이는 줄은 자동으로 가려지지만, 마스킹이 100% 완벽하지 않을 수 있습니다.
   > 계속할까요? (매번 여쭤볼게요 — 이번 대화에서는 다시 묻지 않길 원하시면 말씀해주세요.)"
   - 사용자가 "다시 묻지 마세요"류로 답하면, **이번 대화 세션에 한해서만** 이후 이
     명령을 다시 쓸 때 동의 절차를 생략합니다. 어떤 파일·설정에도 이 선택을 저장하지
     마세요 — 대화가 끝나면 자동으로 초기화됩니다.
2. **도구가 반환한 `maskedText`만 보세요.** 원본 파일을 직접 열어 읽지 마세요 — 도구가
   비밀키로 보이는 줄을 이미 가려서 돌려줍니다. 그래도 마스킹이 완벽하지 않을 수 있으니,
   혹시 `maskedText` 안에 비밀키처럼 보이는 내용이 남아 있으면 **그 내용을 리포트에 절대
   인용하지 말고** 조용히 무시하세요.
3. **판정은 항상 "의심"으로만.** 이 5개 항목은 사람이 봐도 의견이 갈릴 수 있는 판단이라
   `confidence: "의심"`으로만 표시하고 **"확정"이라고 말하지 마세요**. 오탐 가능성을
   항상 함께 안내하세요.
4. **원문을 그대로 인용하지 마세요.** 리포트에는 줄 번호 + 짧은 요약(무엇이 왜 걸렸는지)
   만 적고, 문장을 통째로 옮겨 적지 마세요 — 마스킹 이후에도 남는 노출을 최소화합니다.

## 실행 순서

1. **동의 확인** (위 규칙 1). 동의가 없으면 여기서 멈춥니다.
2. **깊은 검진 도구 실행**:
   ```
   node "${CLAUDE_PLUGIN_ROOT}/lib/checkup-cli.mjs" "<설명서 파일의 절대경로>" --action deep-scan
   ```
   (코덱스는 `checkup.md`와 동일하게 `${CLAUDE_PLUGIN_ROOT}` 대신 저장소 루트에서 `lib/…`로 실행)
3. 결과 JSON의 `hintlessChecks[]`(5개 항목: `id`·`name`·`why`)를 하나씩, `maskedText`를
   근거로 실제로 판단합니다:
   - `conflicting`(앞뒤 모순): 서로 반대되는 지시가 있는지
   - `blind_references`(맥락 없는 참조): 설명 없이 파일·경로만 가리키는 곳이 있는지
   - `no_examples`(예시 없는 규칙): 좋은/나쁜 예시 없이 규칙만 있는 곳이 있는지
   - `bloat`(부풀림): 같은 말 반복·군더더기 지시가 있는지
   - `re-scope-guard`(RE 스코프 누락): 리버스 엔지니어링 관련 내용이 있다면 방어·교육·
     본인소유물 전용 범위가 명시돼 있는지
4. 발견한 항목은 일반 검진 리포트의 `suspects.findings[]`와 같은 톤으로 안내(줄 번호 +
   짧은 이유 + "의심"임을 명시). 아무 것도 못 찾았으면 "5가지 다 봤지만 특별한 문제는
   못 찾았어요"라고 명확히 알려서, "안 봤음"과 구분되게 하세요.

## `maskedLineCount` 안내

`maskedLineCount`가 0보다 크면, "이번 검사에서 비밀키로 보이는 줄 N개를 가리고 나머지만
봤어요"라고 짧게 알려주세요. 0이면 언급하지 않아도 됩니다.
