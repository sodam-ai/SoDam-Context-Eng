SoDamContext — README (한국어)

SoDamContext — AI 사용설명서 건강검진 🩺

코드를 몰라도 AI(클로드코드·코덱스)가 내 프로젝트를 잘 이해하도록, "AI 사용설명서"(CLAUDE.md·AGENTS.md)를 쉬운 한국어로 점검·생성·정리해 주는 도구입니다.

컴퓨터·AI가 처음이어도 괜찮아요. 이 문서는 하나씩 따라 하면 되는 순서로 쓰여 있습니다.

⚠️ 정직한 현재 상태 (2026-07-18 기준)

  • 작동(실사용 라이브 검증 완료): 검진(점검) · 문진(만들기) · 처방(다듬기) · 코덱스 검진 · 동기화(두 설명서 비교) · 예방(저장 전 자동 차단) — 클로드코드·코덱스 양쪽 실제 세션에서 확인됨
  • 보안 강화: 민감한 위치(시스템·자격증명 폴더) 쓰기 자동 거부 기능 추가
  • 코드 완성, CLI 검증 완료(대화형 세션 추가 확인 예정): 정기 점검 알림(마지막 검진 후 며칠 지났는지 자동 안내) · 건강점수(참고용) — 검진 결과에 자동으로 포함되도록 만들었고, 유닛테스트와 명령줄 직접 실행으로 정확성을 확인했습니다. 다만 실제 대화형 검진 세션에서 이 안내가 자연스럽게 나오는지는 아직 추가 확인 전입니다.
  • ⚠️ 클로드코드 호출 방식이 바뀌었습니다(2026-07-18): 예전엔 자연어("설명서 점검해줘")로도 가끔 찾아졌지만, 지금은 /sodam-context:checkup처럼 슬래시 명령을 정확히 입력해야만 작동합니다(더 확실하게 만들기 위한 구조 변경). 코덱스는 영향 없음 — 자연어 그대로 작동합니다.
  • 과장하지 않습니다. "100% 안전·완벽"이라고 말하지 않습니다.

1. 이게 뭔가요

  • AI 코딩 도구(클로드코드·코덱스)는 일을 시작하기 전에 CLAUDE.md / AGENTS.md 라는 파일을 읽습니다. 이 파일이 바로 "AI 사용설명서" 예요. (AI에게 "이 프로젝트는 이렇게 다뤄줘"라고 미리 적어 두는 쪽지입니다.)
  • 이 설명서가 너무 길거나, 비밀번호(키)가 들어 있거나, 서로 모순되면 AI가 헷갈리고, 대답이 부정확해지고, 비용도 늘어납니다.
  • SoDamContext는 그 설명서를 쉬운 한국어로 건강검진하고, 없으면 쉬운 질문 몇 개로 작게 만들어 주고, 문제가 있으면 안전하게 다듬어 줍니다.
  • 어려운 말은 숨깁니다(CLAUDE.md → "AI 사용설명서"). "왜요?"라고 물으면 그때 진짜 이유를 알려줘요.

💡 한 줄 요약: "AI가 내 프로젝트를 잘 알아듣게 해 주는 설명서를, 코드 몰라도 점검·정리할 수 있게 도와주는 도구."

📱 참고(정직): 이 도구는 컴퓨터(Windows·macOS) 의 클로드코드·코덱스 안에서 작동합니다. 휴대폰 앱이 아닙니다. 스마트폰만 있는 경우엔 사용할 수 없어요.

2. 사전 준비물과 필요 프로그램

준비물 필요한 이유 확인 / 설치 방법
클로드코드(Claude Code) 이 도구가 작동하는 곳 이미 쓰고 계시면 OK. 없으면 claude.com/claude-code 안내를 따라 설치

Git 코덱스 설치·로컬 설치 때 저장소 받기 입력창에 !git --version → 숫자가 나오면 OK. 없으면 git-scm.com 에서 설치
(선택) 코덱스(Codex) 코덱스의 AGENTS.md도 다루려면 코덱스 쓰는 분만 필요
  • 운영체제: Windows·macOS 둘 다 됩니다. (이 문서의 경로 예시는 Windows 기준이에요.)
  • 인터넷: 설치할 때만 필요합니다. 검진·문진은 100% 내 컴퓨터 안에서 돌아갑니다(데이터를 밖으로 안 보냄).
  • "입력창" = 클로드코드에서 글을 치는 칸이에요. 이 문서에서 "입력창에 ~치세요"는 거기에 친다는 뜻입니다.

3. 다운로드와 설치 방법

3-1. 클로드코드 (자동 설치, 권장)

클로드코드 입력창에 아래 두 줄을 한 줄씩 붙여넣고 각각 Enter 하세요.

/plugin marketplace add sodam-ai/SoDam-Context-Eng
/plugin install sodam-context
  • 또는 /plugin 만 쳐서 메뉴에서 SoDamContext를 찾아 Install 을 눌러도 됩니다.
  • 설치 후에는 클로드코드를 완전히 껐다 켜세요(재시작). 그래야 명령어가 목록에 떠요.

💡 내 컴퓨터 폴더에서 바로 쓰는 경우(개발·테스트): 위 첫 줄의 sodam-ai/SoDam-Context-Eng 자리에 그 폴더의 절대경로를 넣으세요. 예: /plugin marketplace add D:\...\SoDam-Context-Eng

3-2. 코덱스 (수동 설치)

코덱스에는 플러그인 마켓이 없어서, 저장소를 통째로 받아 그 안에서 씁니다. (스킬 폴더만 복사하면 검진 도구가 쓰는 lib·rules 폴더가 빠져서 "파일을 찾을 수 없어요" 오류가 나요.)

  1. 터미널(명령 프롬프트)에 한 줄씩: 
    git clone https://github.com/sodam-ai/SoDam-Context-Eng.git
cd SoDam-Context-Eng
  2. 코덱스를 이 저장소 루트 폴더에서 시작하세요. (루트에 AGENTS.md·skills·lib·rules가 다 있어요.)
  3. 자세한 단계·FAQ는 저장소의 codex/README.ko.md 또는 이 문서 아래 사용 방법 참고.

💡 원클릭 설치 스크립트(선택, Windows): 저장소의 codex/install.ps1을 받아서 실행하면 위 1~2단계(준비물 확인·clone·AGENTS.md 생성)를 대신 해 줍니다. 이 저장소는 공개(PUBLIC) 저장소지만, 스크립트 파일 하나만 따로 받을 수 있는 링크는 준비돼 있지 않아서, 스크립트 자체를 처음 손에 넣으려면 딱 한 번은 위 1단계(git clone)를 직접 해야 합니다. 실행 정책이 막으면(Windows 보안), 파일을 우클릭 → PowerShell로 실행하거나 powershell -ExecutionPolicy Bypass -File install.ps1로 1회 실행하세요. 자세한 안내는 codex/README.ko.md.

3-3. 제거(Uninstall) 방법

클로드코드

  1. 입력창에 /plugin uninstall sodam-context 를 치고 Enter.
  2. 클로드코드를 완전히 껐다 켜세요(재시작) — 그래야 명령어 목록에서도 깔끔히 사라져요.

코덱스

  • 3-2에서 git clone으로 받은 저장소 폴더를 그냥 삭제하면 끝입니다(레지스트리·설정 파일 등 다른 곳엔 아무것도 안 남아요).

백업(.sodamcontext/backups/)은 어떻게 되나요?

  • 플러그인을 지워도 여러분 프로젝트 폴더 안의 백업은 그대로 남습니다(플러그인은 클로드코드 쪽에서만 지워지고, 백업은 여러분 프로젝트 폴더에 있는 별개의 파일이라서요).
  • 보존하고 싶다면: 아무것도 안 하면 됩니다. 나중에 이 도구를 다시 설치해도 옛 백업을 그대로 되돌리기(restore)에 쓸 수 있어요.
  • 완전히 지우고 싶다면: 각 프로젝트 폴더의 .sodamcontext 폴더를 직접 삭제하세요(탐색기에서 폴더 하나 지우는 것과 같아요). 이 폴더에는 백업 파일과 "마지막 점검 시각" 기록만 있고, 여러분의 CLAUDE.md·AGENTS.md 원본은 들어있지 않으니 안심하고 지워도 됩니다.

4. 빠른 시작

설치·재시작이 끝났다면, 딱 두 가지만 기억하세요.

  1. 이미 설명서가 있을 때 → 점검(검진):

    /sodam-context:checkup

    "어느 파일을 볼까요?"라고 물으면, 점검할 폴더의 CLAUDE.md 경로(절대경로)를 알려주세요.

  2. 아직 설명서가 없을 때 → 만들기(문진):

    /sodam-context:intake

    쉬운 질문 5~6개에 답하면, 미리보기 → "만들까요?" 확인 후 작은 설명서를 만들어 줍니다.

클로드코드에서는 자연어로 못 찾아요 — 반드시 위 슬래시 명령을 정확히 입력해 주세요(예전엔 자연어도 가끔 됐지만, 지금은 구조상 슬래시 명령만 작동합니다). 코덱스는 다릅니다 — 코덱스는 원래부터 슬래시 명령이 없어 자연어로 부르고, 이건 지금도 그대로 작동해요.

5. 실행 방법

이 도구는 직접 켜는 프로그램이 아니라, 클로드코드·코덱스 안에서 명령/자연어로 부르면 작동합니다.

  • 클로드코드: 입력창에 슬래시 명령을 칩니다. 예: /sodam-context:checkup, /sodam-context:intake, /sodam-context:treat.
  • 코덱스: 슬래시 명령이 없으니 자연어로 부릅니다. 예: "내 AGENTS.md 건강검진 해줘", "설명서 고쳐줘". (반드시 저장소 루트 폴더에서 코덱스를 실행하세요.)
  • 검사할 파일은 절대경로로 알려주면 가장 정확합니다. 예: C:\내프로젝트\CLAUDE.md.

6. 사용 방법

6-1. 검진(점검) — ✅ 작동

  1. /sodam-context:checkup 입력.
  2. "어느 파일?" 물으면 절대경로 알려주기.
  3. 잠시 후 쉬운 리포트가 나옵니다:
    • "문제 ○건" 처럼 개수를 가장 먼저 보여줘요.
    • 비밀번호/키가 있으면 가린 채(sk-ant-…REDACTED)로만.
    • 낡음·자동생성 미정제·스킬누수 같은 항목은 "의심"으로(오탐 가능성 함께 안내).
    • 통째 붙여넣기(코드블록이 너무 길게 그대로 들어있는 경우)는 줄 수라는 구조만으로 판단 가능해 "확정" 문제로 잡아요.
    • 참고 점수(예: "85점")가 개수 뒤에 보조로 붙어요 — 항상 "참고용(검증 전)" 이라는 말이 같이 나옵니다. 아직 여러 사람 데이터로 검증된 공식 점수가 아니라는 뜻이에요(과장 방지 — §9 참고).
    • 마지막 검진 후 30일이 넘었으면 "이번 기회에 다시 점검해볼까요?" 정도로 짧게 안내해요(자동으로 알림이 오는 건 아니고, 검진을 실행한 그 순간에만 비교해요). 30일이 안 지났거나 이번이 첫 검진이면 이 안내 자체가 안 나와요.
    • 더 궁금하면 왜요? 라고 답하면 이유·근거(참고 점수의 계산 근거 포함)를 설명해요.

6-2. 문진(만들기) — ✅ 작동

  1. /sodam-context:intake 입력.
  2. "어느 폴더?" 물으면 경로를 주거나 "지금 이 폴더" 라고 답하기.
  3. 쉬운 질문에 하나씩 답하기(무슨 프로젝트/언어·도구/꼭 지킬 규칙/하지 말 것/말투).
  4. AI가 만들 내용을 먼저 보여주고 "이대로 만들까요?"라고 물어요 → 네 라고 해야 그때 파일이 생겨요.
  5. 만든 설명서는 200줄 이하·비밀키 0. 이어서 "검진도 해볼까요?"에 네 하면 점검까지.

6-3. 처방(다듬기) — ✅ 작동(라이브 검증 완료)

  1. 검진에서 문제가 나오면 /sodam-context:treat 입력.
  2. 백업을 먼저 뜨고, 무엇을 바꿀지 미리보기를 보여줘요.
  3. 네 라고 해야만 실제로 고칩니다(중복 줄·불필요한 빈 줄 정리).
  4. 되돌리기(restore) 지원 — 마음에 안 들면 백업으로 복구.
  5. 안전·금지 규칙 줄(예: "절대", "never", "비밀번호 금지")은 자동으로 보존합니다(지우지 않아요).

⚠️ 처방은 실제 세션 라이브 검증까지 완료됐습니다(안전키워드 100% 보존·되돌리기 정확성 확인). 그래도 처음 쓸 땐 중요한 파일은 따로 복사해 두는 걸 권장합니다.

6-4. 깊은 검진(선택 기능) — ✅ 작동

일반 검진(6-1)이 "이런 것도 더 볼 수 있어요"로만 소개하고 넘어가는 5가지 항목(모순·맥락 없는 참조·예시 없는 규칙·부풀림·RE 스코프 누락)을 AI가 실제로 판단하게 하고 싶을 때 씁니다.

  1. /sodam-context:checkup-deep 입력.
  2. 이 기능은 일반 검진과 다르게 AI가 설명서 내용을 직접 읽습니다(비밀키로 보이는 줄은 자동으로 가려지지만, 마스킹이 100% 완벽하진 않을 수 있어요) — 그래서 실행 전 매번 동의를 먼저 구합니다. "네" 또는 "계속해줘"라고 답해야 진행돼요(이번 대화에서만 다시 안 묻길 원하시면 그렇게 말씀하실 수 있어요).
  3. 5가지 항목을 하나씩 실제로 판단해 알려줍니다. 판정은 항상 "확정"이 아니라 "의심" 으로만 표시되고(오탐 가능성 있음), 문제를 못 찾으면 "5가지 다 봤지만 못 찾았어요"라고 명확히 알려줘요 (조용히 넘어가지 않아요 — "안 봄"과 "봤는데 없음"을 구분하기 위해서예요).
  4. 일반 검진보다 토큰(비용)을 더 씁니다. 매번 필요할 때만 선택적으로 쓰는 걸 권장해요.

7. 작동 방법

  • 검진: 도구가 원본 파일을 직접 열지 않습니다. 속 검사기(checkup-cli.mjs)를 돌려 결과(요약 JSON)만 봐요. 그래서 비밀키가 새지 않습니다. 리포트는 점수 대신 "문제 ○건", 비밀키는 가린 채로만 보여줍니다.
  • 문진: 질문 → 미리보기 → "만들까요?" 확인 → 그때만 파일 생성. 묻지 않고 마음대로 만들지 않습니다.
  • 처방: 백업 먼저 → 미리보기 → 확인 → 안전하게 쓰기(임시파일에 쓴 뒤 이름 바꾸기 방식이라, 도중에 멈춰도 원본이 안 깨져요). 처방 뒤엔 파일이 더 작아져야 성공으로 봅니다.
  • 코덱스(AGENTS.md): 코덱스는 상위 폴더·전역 설명서까지 합쳐서 읽어요. 검진이 그 합산 용량(32KiB 한도) 까지 확인합니다. (한글은 글자당 3바이트라 글자 수보다 용량이 큽니다.)
  • 정기 점검 알림: 검진할 때마다 파일 절대경로별로 "마지막으로 언제 점검했는지"만 시각(타임스탬프)으로 기록해 둡니다(내용은 저장하지 않음). 다음 검진 때 그 시각과 비교해서 30일이 넘었으면만 짧게 안내해요. 백그라운드에서 자동으로 알림이 오지 않습니다 — 검진을 실행하는 그 순간에만 비교합니다.
  • 참고 점수(건강점수): 새로 파일을 읽어서 계산하는 게 아니라, 검진이 이미 찾아낸 문제 개수(확정 문제는 -15점, 의심 항목은 -5점, 100점 만점)로 그 자리에서 계산해요. 계산 방법을 전부 공개하는 투명한 뺄셈식이라 "왜 이 점수예요?"라고 물으면 그대로 풀어서 설명할 수 있어요.
  • 깊은 검진(선택, 2026-08-03 추가): 위 검진과 달리 이 기능은 동의를 구한 뒤에만 설명서 내용을 AI가 직접 읽습니다(비밀키로 보이는 줄은 읽기 전에 미리 통째로 가려서 전달). 판정은 항상 "의심"으로만 표시되고, 원문을 그대로 리포트에 인용하지 않습니다. 일반 검진(도구가 원본을 직접 안 읽는 방식)의 유일한 예외로, 명시적으로 선택해야만 켜지는 기능입니다.

12. 아키텍처

기술에 관심 있는 분을 위한 내부 구조입니다. (몰라도 사용에는 지장 없어요.)

  • 데이터 주도(Data-driven): 검진·처방의 판정 규칙은 코드가 아니라 rules/*.json 에 있습니다. 새 검진을 추가하려면 JSON 배열에 객체 하나 넣으면 돼요(코드 변경 0).
  • CLI–JSON 경계(안전의 핵심): AI·스킬은 원본 파일을 직접 읽지 않고, lib/checkup-cli.mjs 가 내보내는 요약 JSON만 봅니다. 비밀키 '값'은 어떤 결과·로그에도 들어가지 않아요.
  • 엔진(lib) 구성: scan-secrets(비밀키 탐지 + maskSecretsInLines로 깊은 검진용 줄 단위 마스킹) · checkup-rules(크기·린트중복·의심 탐지) · intake-verify(생성물 안전 게이트) · treat+treat-verify(정리·안전키워드 보존·회귀검증) · backup(원자적 백업·복구) · codex-merge(코덱스 병합체인·32KiB) · path-safety(민감 경로 쓰기 차단) · checkup-cli(오케스트레이터: 검진/백업/미리보기/적용/복구/깊은검진).
  • 의존성 0: 외부 npm 패키지를 쓰지 않습니다(공급망 위험 최소화). Node 18+ ESM, 100% 로컬(네트워크 전송 0).
  • 진입점(명령) 5종: sodam-context:intake·sodam-context:checkup·sodam-context:treat·sodam-context:sync·sodam-context:checkup-deep(2026-08-03 추가) — 클로드코드는 슬래시 명령, 코덱스는 자연어(같은 내용을 commands/*.md에서 읽음).
  • 자연어 자동탐색 없음(2026-07-18, 의도적 설계): 클로드코드 쪽엔 예전에 있던 "스킬"(자연어로 자동 찾아지는 기능 등록 방식)을 두지 않습니다 — 스킬을 두면 /sodam-context:checkup(정확한 형태)과 /sodam-context-checkup(자동 노출된 하이픈 형태)이 동시에 떠서 헷갈렸기 때문입니다. 그래서 클로드코드에서는 위 4개 명령을 슬래시로 정확히 입력해야만 호출됩니다. 코덱스는 원래 스킬이라는 개념 자체가 없어(자연어+AGENTS.md 안내만으로 동작) 이 변경의 영향을 받지 않습니다.

13. 보안과 데이터 흐름

  • 비밀키 미열람(T1): 도구는 비밀키 '값'을 읽거나 출력하지 않습니다. "있다"까지만 확인하고 가려서(sk-ant-…REDACTED) 보여줍니다. 자동으로 지우지 않아요(오탐 위험 때문).
  • 자동 변경 없음(Fail-Closed): 사용자가 "네" 라고 하기 전에는 파일을 만들지도 고치지도 않습니다.
  • 네트워크 0: 검진·문진·처방은 내 컴퓨터 안에서만 돌아갑니다. 인터넷은 설치할 때만 필요.
  • 원자적 쓰기 + 백업 우선: 처방은 임시파일에 쓴 뒤 이름을 바꿔 반영하고, 백업이 실패하면 즉시 중단합니다.
  • 적용(apply) 자체가 백업을 강제합니다(2026-07-27 강화): 대화 안내 문구에만 기대지 않고, 처방을 적용하는 코드 자체가 내부적으로 반드시 백업을 먼저 만든 뒤에만 원본을 바꿉니다 — 어떤 경로로 호출되어도 백업 없이 덮어써지지 않습니다.
  • 안전키워드 보존: "절대/금지/never/must/항상/secret/force push" 같은 중요 규칙이 든 줄은 자동 보존(정리에서 제외).
  • 민감한 위치엔 아예 쓰지 않음: 처방·되돌리기 대상이 홈 폴더 자체·자격증명 폴더(.ssh·.aws 등)·시스템 폴더로 잘못 지정되면, 실행 전에 자동으로 거부하고 이유를 알려줍니다.
  • 검진은 지정한 파일 하나만 봅니다: 코덱스(AGENTS.md)는 상위 폴더·전역 설명서까지 합쳐서 확인하지만, 클로드코드(CLAUDE.md)는 지금은 지정한 파일 하나만 봅니다. 하위 폴더의 별도 CLAUDE.md나 .claude/rules/에 규칙을 나눠 두셨다면, 그 파일들은 자동으로 훑지 않으니 각각 따로 검진해 주세요.
  • 저장 전에 미리 막습니다(예방, 2026-07-17 실사용 라이브 확인 완료): CLAUDE.md·AGENTS.md에 확정된 비밀키가 들어가거나 너무 길어지면(300줄/32KB 이상) 저장 전에 막고, 200~299줄처럼 애매한 경우는 "그래도 저장할까요?" 로 한 번 더 확인합니다. 판정 로직·연동 프로토콜을 코드 레벨에서 검증한 데 이어, 실제 사용 세션에서 252줄짜리 내용을 저장하려 할 때 이 확인창이 정말로 뜨는 것까지 직접 확인했습니다(자동승인 아닌 진짜 사용자 확인). 이 설명서 두 파일 외에는 어떤 파일 작업도 건드리지 않습니다.
  • 두 설명서 동기화는 합치지 않고 알려만 줍니다: CLAUDE.md와 AGENTS.md 중 한쪽에만 있는 안전 규칙(절대/금지/never/must/secret 등)을 찾아 줄 번호로 알려드립니다. 파일을 자동으로 합치거나 고치지 않으며, 파일 내용 자체도 결과에 담지 않습니다(줄 번호만).
  • 되돌리기 소스도 검증합니다(2026-07-13 추가): "되돌리기(restore)"는 이 도구가 실제로 만든 백업 폴더(.sodamcontext/backups/) 안의 파일만 소스로 허용합니다. 그 밖의 임의 파일을 지정하면 거부합니다 — 그래야 엉뚱한 파일 내용이 실수로 설명서에 복사되는 걸 막을 수 있습니다.
  • 백업 대상도 검증합니다(2026-07-27 추가): "백업(backup)"을 뜰 때도 대상 경로가 자격증명 폴더(.ssh·.aws 등)나 시스템 폴더처럼 민감한 위치면 실행 전에 거부합니다 — 그래야 실수로 지정한 자격증명 파일의 내용이 백업 폴더에 그대로 복사되는 걸 막을 수 있습니다.
  • 정기 점검 알림도 내용을 저장하지 않습니다(2026-07-15 추가): "마지막 점검이 언제였는지" 기록은 파일의 절대경로 문자열 + 시각(타임스탬프) 문자열만 프로젝트 폴더 안(.sodamcontext/last-checkup.json)에 남깁니다. 설명서의 실제 내용은 이 기록 어디에도 들어가지 않습니다.
  • 참고 점수는 블랙박스가 아닙니다(2026-07-15 추가): 점수 계산에 새로운 파일 읽기가 없습니다 — 검진이 이미 만들어 둔 "확정 문제 개수"·"의심 개수"만으로 그 자리에서 뺄셈합니다. 가중치(확정 -15점, 의심 -5점)는 코드가 아니라 rules/thresholds.json에 숫자로 적혀 있어 누구나 확인할 수 있고, "왜?"라고 물으면 계산 근거를 그대로 보여줍니다.
  • 정직한 한계: 정해진 패턴만 잡으므로 "100% 안전·완벽 탐지"는 보장하지 않습니다(참고용). 중요한 키는 직접 재발급/관리하세요.
  • 깊은 검진만의 예외(2026-08-03 추가): 위 "비밀키 미열람" 원칙의 유일한 예외입니다. /sodam-context:checkup-deep은 규칙만으로 못 잡는 5가지 항목을 판단하기 위해 AI가 설명서 내용을 직접 읽습니다 — 그래서 실행 전 매번 명시적 동의를 구하고, 넘기기 전에 비밀키로 보이는 줄은 통째로 가려서 전달합니다(마스킹이 100% 완벽하지 않을 수 있다는 한계도 함께 안내합니다). 판정은 항상 "의심"으로만 표시하고 "확정"이라 말하지 않으며, 리포트에 원문을 그대로 인용하지 않습니다. 이 예외 경로가 자격증명 폴더(.ssh·.aws 등)를 대상으로 지정돼도, 처방·백업·되돌리기와 동일하게 실행 전 자동으로 거부됩니다.

15. 자주 묻는 질문

Q. "AI 사용설명서"가 정확히 뭔가요? A. AI 코딩 도구가 일 시작 전에 읽는 CLAUDE.md(클로드코드용)·AGENTS.md(코덱스용) 파일이에요. "이 프로젝트는 이렇게 다뤄줘"라고 적어 두는 쪽지입니다.

Q. 내 파일 내용이 밖으로 나가나요? A. 아니요. 검진·문진·처방은 100% 내 컴퓨터 안에서 돌아갑니다. 인터넷은 설치할 때만 필요해요.

Q. 비밀번호를 자동으로 지워주나요? A. 아니요. "있다"까지만 확인하고 가려서 보여줄 뿐, 자동으로 지우지 않습니다(오탐 위험). 직접 확인하고 재발급하세요.

Q. 참고 점수(건강점수)는 믿을 만한가요? A. "참고용(검증 전)" 이라는 라벨이 항상 같이 나오는 이유가 그 답입니다 — 아직 여러 사람의 실제 사용 데이터로 다듬어진 공식 점수가 아니에요. "문제 ○건"이 먼저 나오는 진짜 정보고, 점수는 그 뒤에 붙는 참고용 보조 지표입니다. 계산 방법은 숨기지 않고 전부 공개해요(확정 문제 1건당 -15점, 의심 1건당 -5점, 100점 만점).

Q. "마지막 점검 후 며칠 지났어요" 안내는 어떻게 오나요? A. 백그라운드에서 갑자기 알림이 오는 게 아니에요. 검진(/sodam-context:checkup)을 실행하는 바로 그 순간에만 지난번 점검 시각과 비교합니다. 30일이 안 지났거나 이번이 첫 검진이면 이 안내 자체가 아예 안 나와요(불필요한 알림 방지).

Q. 한글이 깨져요. A. Node.js가 v18 이상인지 확인하세요. Windows에서는 터미널 인코딩이 UTF-8인지도 확인해요.

Q. 자동 허용(권한) 모드에서 써도 되나요? A. 자동 허용 모드는 확인 단계를 건너뛸 수 있어요. 안전을 위해 기본(ask) 모드를 권장합니다.

Q. 클로드코드와 코덱스를 같이 써도 되나요? A. 네. 같은 프로젝트에서 클로드코드는 CLAUDE.md, 코덱스는 AGENTS.md를 각각 읽어요. 두 파일이 공존해도 문제없습니다.

Q. 업데이트는 어떻게 하나요? A. 클로드코드는 ! claude plugin marketplace update sodamcontext-marketplace 후 재시작. 코덱스(로컬 저장소)는 폴더에서 git pull.

Q. 클로드코드에서 "설명서 점검해줘"라고 말로 했는데 안 찾아져요. A. 정상입니다(고장 아님). 2026-07-18부터 클로드코드는 자연어 자동탐색 기능(스킬) 없이 슬래시 명령 전용으로 바뀌었습니다. /sodam-context:checkup처럼 정확히 입력해 주세요. 코덱스는 원래부터 자연어로만 부르는 구조라 이 변경과 무관하게 계속 자연어로 작동합니다.

Q. 비용이 드나요? A. 이 도구 자체는 로컬에서 돌아 별도 요금이 없지만, AI(클로드·코덱스) 사용에는 각 제공사의 요금이 적용됩니다(우리 범위 밖).

Q. "깊은 검진"은 일반 검진과 뭐가 다른가요? A. 일반 검진은 도구가 원본 파일을 직접 안 읽고 요약 결과만 보지만, 깊은 검진(/sodam-context:checkup-deep)은 모순·부풀림처럼 규칙만으론 못 잡는 걸 AI가 직접 판단해야 해서 예외적으로 내용을 읽습니다. 그래서 매번 동의를 먼저 구하고, 비밀키로 보이는 줄은 미리 가리며, 일반 검진보다 토큰(비용)도 더 씁니다. 필요할 때만 선택적으로 쓰세요.
